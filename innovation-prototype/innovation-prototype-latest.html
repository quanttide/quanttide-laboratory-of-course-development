📖 一、量潮是谁

在开始学习之前，先理解量潮是怎样一家公司，以及为什么量潮会做课堂。点击下方课时，展开即可学习。

1.1 我们从哪里来：量潮的创立故事阅读 10 min▾
量潮不是"做出来的公司"，而是从一个真实研究课题里长出来的。

量潮的源头，可以追溯到 2016 年在厦门大学王亚南经济研究院（WISE）成立的本科生课题组——China's Prices Project（CPP）。创始人是 WISE 经济学国际化试点班 2014 级本科生张果。

课题组当时在做的课题，是参考 MIT 的 Billion Prices Project，用爬虫技术采集电商平台商品价格，编制"中国线上价格指数"（线上 CPI / iCPI）。这个课题真正塑造量潮的，不是某个技术，而是它一开始就"以真实问题驱动、以数据为研究对象、用工程方法解决，并把过程公开记录"。

  • 2016 — 源头：在厦大成立课题组，用爬虫 + 数据工程解决真实的线上价格指数问题
  • 2017 — 转折：公开发布《CPP 3.0：从课题组到科技公司》，开始主动思考公司化
  • 2018 — 成立：注册成立厦门量潮科技有限公司
  • 此后 — 生长：科研服务逐渐沉淀出课程、咨询与软件产品

我们的名字"量潮"，寓意"引领定量分析时代潮流"。

一句话记忆：量潮是从厦大一个真实研究课题里长出来的公司——"问题驱动、数据驱动、工程驱动"从第一天起就在它的基因里。
1.2 量潮到底在做什么阅读 15 min▾
围绕同一套数据与工程能力，同时做项目、育人才、做咨询、造工具。

与其用"部门图"理解量潮，不如看它掌握了哪几种能力。量潮的四种能力处理不同的问题，却共用同一个内核——数据和工程：

数据解决真实的数据问题——科研数据服务：数据采集、清洗、文本挖掘
课堂把能力变成人才培养——产教融合课程、微专业、生产实习
咨询把方法用于企业问题——创新咨询、创业咨询
云把重复能力产品化——DevOps 工具链、数据云、支付云

它们形成一个闭环：科研服务产生真实问题 → 方法与工程实践 → 沉淀为课程（培养人）与云工具（沉淀技术）→ 反过来支撑新的真实项目。

举个具体的例子——量潮云。公司长期在做软件发布，流程重复且容易出错，于是把发布规则一条条整理出来，写成了开源工具 qtcloud-devops（一个自动化发布命令行工具，用 Rust 编写）。自己的项目先用起来，再逐渐打磨成可复用的产品。这就是"沉淀技术"最朴素的样子。

一句话记忆：量潮围绕同一套数据与工程能力，同时做项目、育人才、做咨询、造工具——科研服务产生真实问题，课堂培养解决问题的人，云把重复方案沉淀成工具。
1.3 量潮是怎么组织起来做这些事的阅读 8 min▾
不靠一张"部门图"，靠一套能自我运转的方式。

量潮的业务资产、开源仓库、课程与工具仍在快速演化，不太适合被画成一张固定的组织架构图。更稳定的理解方式是看它怎么运转：

  • 围绕能力组织，而不是围绕部门 — 数据 / 课堂 / 咨询 / 云四种能力相互咬合，各自解决什么问题很清楚
  • 真实项目带路 — 先有真实需求，再长出方法、课程与工具，而不是先设计好组织再找事做
  • 扁平、自组织 — 团队规模小、信任氛围好；为了赶客户截止时间，团队几乎独立"发明"了自己的工作流程，创始人从一线退下后，新人也能在几天内接手一套新工作方法
  • 用制度代替人治 — 把发布流程、验收机制、考核标准显式写成规则，让"能力"沉淀在系统里，而不是个人身上
  • 客户与项目对接 — 由项目经理 / 商务经理牵头，内部管理负责人与技术负责人参与设计与验收
  • 实训基地 — 在量潮创新联盟旗下运营"助研 / 创赛 / 技术"三类，是组织培养人才的延伸
一句话记忆：量潮不用"部门图"定义自己，而用"能不能解决真实问题"来组织——做真实项目 → 沉淀方法 → 做成课程和工具 → 培养新人 → 再解决新的问题。
1.4 一个真实案例：浙江理工大学阅读 10 min▾
从一门《生产实习》课程开始，长成一个持续深化的大数据课程体系。

量潮与浙江理工大学围绕大数据相关课程开展持续校企合作，合作从单门课程逐渐扩展到课程体系建设、生产实习和企业导师参与。创始人张果担任浙理工计算机系企业导师，主导课程设计与授课。

  • 一门课起步 — 2024 年底与浙理工计算机系开设《生产实习》教学实习课程
  • 长成体系 — 合作扩展到《大数据导论》《数据工程》《数据科学》等课程与《大数据微专业》
  • 议事型课堂 — 把企业周会决策流程搬进课堂，以真实商业难题为案例，训练解决问题的"元能力"
  • 从"拧螺丝钉"到"参与真实生产" — 学生自主选题、自主执行、向"总部"Sale，复用企业验收机制考核

合作课程6 门

合作方式课程建设 + 生产实习 + 企业导师

为什么我们讲这个案例？因为它是量潮"产教融合"如何落地的样板：课堂里训练什么，实习就要求什么；实习里要求什么，招聘就考察什么。换句话说，教学、实习和招聘逐渐使用"同一套卷子"。

一句话记忆：量潮课堂里学的东西，不是脱离业务的"课程知识"，而是量潮真实工作方式的一部分——你将来要面对的要求，和量潮自己人面对的一样。

1.2 量潮解决什么问题？围绕数据和工程，解决科研、教学与企业中的真实问题。

🏢 二、量潮课堂为什么存在

为什么一家数据科技公司要办课堂——量潮课堂为什么存在。点击下方课时，展开即可学习。

2.1 产教融合：量潮课堂为什么存在阅读 15 min▾
量潮课堂建立在一种"产教融合"思路上：真实业务产生问题、案例和工程经验，再把这些经验转化为课程和人才培养。

先说明一点：这是量潮目前对自身业务循环的一种理解，而不是一条被验证完毕的定律——它正在被实践持续检验。按这种理解，真实项目提供问题与方法论，课堂把这些经验转化为课程，培养出的学生再回到真实项目中。

  • 企业授课 — 作为浙江理工大学大数据微专业的官方企业授课单位，把一线工程规范带进课堂，开设《大数据技术》《大数据项目实践》等专业课
  • 议事型课堂 — 把企业周会决策流程搬进教学，以已解决的真实商业难题为案例，训练解决问题的"元能力"
  • 实训基地 — 与高校老师联合运营产学研一体化平台，分"助研 / 创赛 / 技术"三类
  • 生产实习 — 学生参与真实生产流程（自主选题 → 执行 → 向总部 Sale），而非只做"拧螺丝钉"式的数据处理

这条思路的根基是：课程里讲的每一个案例，都来自量潮真实跑过的项目；课上练的每一道题，都可能对应一个真实需求。

一句话记忆：先有真实业务，再把它变成课程；课程又反哺业务的人才池。教学不是副业，它倒逼我们把"做得不错"变成"说得清楚"。
2.2 课堂为什么不只是一门课：人才、案例与知识资产阅读 12 min▾
课程的价值不只有学费，还包括人才发现、案例积累和方法迭代。

课程确实有定价：微专业全套 4188 元，一对一 Vibe Coding 课程 1000 元/小时（在校学生 500 元/小时）。但在量潮的账本上，一门课的价值远不止学费，还包括三种"外部性"：

  • 人才沉淀 — 课堂允许我们更长期、更真实地观察一个人的能力：沟通方式、遇到问题的反应、完成工作的质量。对认可的工作成果，量潮还会发放标准化推荐信，给求职者真实的企业背书
  • 案例沉淀 — 好的课程成果，可以在获得授权的前提下进一步整理为教学案例（选题、Demo、方法），成为公司和下一届学员共用的素材
  • 方法沉淀 — 学生遇到的新问题，反过来推动课程、工具和方法升级——教的过程本身也在逼公司把话说清楚

关于考核标准，量潮希望逐渐让教学评价与招聘评价使用同一套能力标准，只是要求深度不同。例如：课程要求达到"能够完成"，招聘可能要求达到"能够独立、高质量完成"。

一句话记忆：课程的价值不只有学费，还包括人才发现、案例积累和方法迭代——这是它作为"系统"而不是"一门课"的原因。
2.3 谁在上课：三类学习者的真实画像阅读 10 min▾
用户画像不是"分群"，而是能回答"他是谁、为什么来、为什么选量潮"。
在校学生已经学过编程或数据课程，但缺少完整真实项目；不知道企业到底如何验收工作。最大的痛点是没有"能讲清楚的作品"。选量潮，是因为这里给的是真实项目 + 企业验收标准
招聘候选人希望进入量潮，但简历不足以证明实际能力。最大的痛点是"能力无法被证明"。选量潮，是因为考核期就用真实任务证明自己，且考核期间可获得培训资源与标准化推荐信
高客单个人学员已经能使用 AI 工具，但卡在"知道工具、不会构造工作流"。愿意为高密度反馈和个性化指导付费，选量潮的一对一 Vibe Coding 课（按小时计费）

课堂之外，量潮还服务两类 B 端客户：高校经管科研团队（数据清洗、文本挖掘等科研数据服务）和中小高新科技企业（企业数据咨询、解决方案）。

一句话记忆：三类人为什么选量潮？因为这里提供的不是"课程"，而是"能证明能力的真实机会"——这正是简历和证书给不了的东西。
2.4 能力规模化：从实训基地到开放平台阅读 8 min▾
规模化不是多招老师、多招工程师，而是让同样质量的工作不再依赖某一个人。
  • 实训基地阶梯 — 助研项目（科研入门训练营）→ 实训生计划（深度实践阶段），层层筛选培养
  • 产品化 — 把非标的数据服务拆成可预测、可复制的标准化交付（数据蓝图 / 数据集 / 数据报告）
  • 工具化 — 把工程实践沉淀为开源工具（qtcloud-devops 等），发布到 GitHub 组织 quanttide
  • 内容"左移" — 课程内容不断前置降级（当前实践课标准 = 之前生产实习标准），保持业界领先
  • Build in Public — 开源公司可公开的文档与代码，降低信任成本，吸引共创者

这条路径的核心，是把"少数人手里的能力"沉淀为"可复制、可规模化的系统"——让同样质量的工作，不再依赖某一个具体的人。

一句话记忆：人的经验 → 标准 → 工具 → 平台。规模化的本质不是加人，而是让能力离开个人、进入系统。

🔧 三、工作方法论

量潮是怎么做事的——这些方法你马上就能直接复用。点击下方课时，展开即可学习。

3.1 从原型到成品：快速开发流程阅读 15 min▾
先用原型快速验证想法，再用确定性规则把流程固化，最后让 AI 参与判断。

量潮做开发的节奏是"原型先行"：先把想法快速变成一个能看、能用的原型，验证之后再打磨成成品。原型的目的不是"做得快"，而是尽快把抽象判断变成可以验证的东西——用最小成本检验想法是否值得继续。

一个想法从原型走向成品的完整循环是：

  • 原型 — 用最小成本把想法变成可验证的东西
  • 验证 — 判断方向对不对，值得不值得继续投入
  • 重构 — 保留对的，调整错的，逐步打磨质量
  • 自动化 — 把重复步骤写成规则（以软件发布为例：核对版本号与 CHANGELOG → 打 Git Tag → 发 Release → 触发 CI/CD 自动构建分发）
  • 产品化 — 让这套流程能复用于同类工作

这套哲学叫"先造围栏，再上智能体"：高确定性的事用规则引擎固定，越往上不确定性越强，越需要 AI 介入判断——就像盖楼，AI 的认知能力在一层层构建中被逐步推高。

一句话记忆：原型 → 验证 → 重构 → 自动化 → 产品化。原型的意义不是快，而是把抽象判断变成可以验证的东西。
3.2 知识工程入门（Baby 版教程）阅读 15 min▾
知识不是"记在脑子里"，而是像代码一样被结构化、被版本化、被复用。

量潮把知识当工程来做：公司可公开的文档、代码、工作方法，全部开源到 GitHub；内部还有"第二大脑"式的知识系统（创始人工作记忆、公司知识库）。为什么要这么认真？因为知识只有在"能被检索、能被复用、能被交接"时，才真正成为资产。

入门只需要三步：

  • 记录 — 把做了什么、为什么这么做写下来。这是工作日志的起点
  • 结构化 — 用固定模板（问题 / 方法 / 结果 / 反思）组织，让它能被检索
  • 复用 — 让知识跨时间、跨人员继续发挥作用。这是知识工程的最终目的

公开是一种可选的传播方式，而不是必经步骤：有的知识适合 GitHub 公开（能倒逼你把"做得不错"变成"说得清楚"），有的适合内部共享，有的必须保密——商业秘密、个人信息、客户合同限制，都要守好边界。

这份《知识工程入门》有面向非技术岗位的 Baby 版教程——不懂编程也能开始，用的就是上面的三步。

一句话记忆：记录 → 结构化 → 复用，能公开的再公开。知识工程的起点不是工具，而是"把经验写下来"这个习惯。
3.3 Web Coding 基础入门阅读 12 min▾
AI 是编程搭档，代码是思考的副产品。

量潮倡导的 Web Coding（Vibe Coding），不是"让 AI 替你写代码"，而是人和 AI 结对：你用自然语言描述意图，AI 生成初稿，你负责判断和重构。

  • 以重构为中心 — 把 AI 生成的"毛坯房"代码，逐层升级为"精装房"。中间最重要的动作是持续重构
  • 代码是思考的副产品 — 真正值钱的是你对问题的理解，代码只是表达；理解到位了，代码自然会好
  • 沉淀 Prompt 与工作流 — 好的提问习惯和协作 Workflow，比单次生成结果更重要

这套方法取材于公司日常的研发心得，配套于大数据系列课程，也是量潮对每个新人的基础要求。AI 降低了"写出代码"的门槛，但提高了"判断代码是否正确"的重要性——你仍然需要持续检查、测试、编辑 AI 的输出，并决定什么时候该人工介入。

一句话记忆：AI 负责提高产出速度，人负责定义问题、判断结果和保证质量——不是"让 AI 写"，而是"和 AI 一起写"。
3.4 工作日志 + 复盘方法论阅读 8 min▾
把每天的工作写下来，是量潮沉淀能力的最小单位。

工作日志记录"做了什么、为什么、结果如何"；复盘在此基础上多问一句"哪里可以更好、下一次怎么做"。量潮把"工作日志 + 复盘"做成标准模板，让经验能从个人身上流到组织里。

复盘只需要三问：

  • 目标是什么？结果符合预期吗？
  • 哪里做得好，哪里出了问题？
  • 下一次，哪一步可以不同？

这套方法还和量潮引入的 OODA 循环（观察 → 判断 → 决策 → 行动）配套：快速感知变化、做出决策，再把反馈变成下一步动作。

一句话记忆：工作日志不是汇报工具，而是给未来的自己和协作者留下上下文；复盘让"经验"变成"方法"——这是你每天都能做的最小能力投资。
📌 本章小结 · 把它们串成一个工作循环

3.1 怎么快速出成品？原型 → 验证 → 重构 → 自动化 → 产品化，尽快把判断变成可验证的东西。

3.2 知识怎么沉淀？记录 → 结构化 → 复用，能公开的再公开。

3.3 怎么和 AI 协作？AI 提高产出速度，人负责定义问题、判断结果和保证质量。

3.4 怎么持续进步？工作日志给未来留上下文，复盘把反馈变成下一步动作。

这四节不是四个并列方法，而是同一个循环：快速行动 → AI 协作 → 记录过程 → 复盘 → 沉淀为组织知识。

💡 四、量潮正在探索什么

公司正在试着成为什么——而不是"已经是什么"。点击下方课时，展开即可学习。

先说清楚：这一章不是"量潮已经是什么"，而是"量潮目前正在试着成为什么"。这里的判断可能随着实践继续变化——正因为这些方向还在迭代，它们才值得你带着观察去学，而不是当作结论去背。
4.1 Build in Public：为什么尽可能公开阅读 15 min▾
公开不是放弃护城河，而是把信任成本砍掉。

量潮"尽可能公开"——文档、代码、工作方法、甚至不少决策过程，都开源到 GitHub 组织 quanttide。这在大多数公司看来很反常，但量潮的理由非常实际：

  • 信任成本最低 — 客户、学生、候选人看到你的真实工作方式，比任何宣传都可信
  • 吸引共创者 — 透明会吸引认同这套工作方式的人加入（员工、学员、合作者）
  • 倒逼质量 — 能被公开的东西，必须经得起审视

但要强调：量潮实行的是一种"尽可能公开、但存在边界"的策略，而不是无条件公开。成熟的 Build in Public 不是"什么都公开"，而是知道什么应该公开、什么时候公开、公开到什么粒度。至少这些不公开：

  • 客户数据与个人信息
  • 商业秘密与未授权成果
  • 账号密钥与基础设施凭据
  • 受合同 / NDA 限制的信息

这套做法背后是一个通用循环：需求 → 处理 → 交付 → 记录 → 传播——所有业务都走同一个循环，而"记录与传播"正是把每次工作变成公共资产的一步。

一句话记忆：Build in Public 不是情怀，是策略——用透明换信任，用公开倒逼质量，但要永远清楚"哪些不能公开"。
4.2 多业务平衡：一个内核，四个方向阅读 18 min▾
数据、课堂、咨询、云看起来是四件事，其实是一个内核。

量潮的多业务，目前的理解是同一个内核 × 四个投射方向：四个方向是——数据（做真实项目）、课堂（培养人才）、咨询（解决企业问题）、云（把重复方案做成工具）。它们共享方法论、共享案例库、共享人才池。

但"内核到底是什么"，量潮自己也还在验证。历史上它一直是数据工程能力；可随着咨询、制度设计、组织方法、知识工程、AI Coding、课程设计的加入，一个更有扩张性的候选正在浮现——"把非结构化经验，沉淀为数据、规则、工具和课程的能力"。这是目前正在被检验的判断，而不是结论。

四条业务线之间的"传动链条"是：

  • 项目产生真实问题与方法 →
  • 方法沉淀为课程与工具 →
  • 课程培养出人才、工具降低重复成本 →
  • 人才与工具反哺下一个项目

管理层会用"互搏"来检验内核的标准化程度：同一个内核能不能同时支撑多个业务？如果能，说明它真的被沉淀成了标准，而不是某个人的经验。

一句话记忆：一个内核 × 四个方向，靠"传动链条"互相输血，靠"互搏"检验标准——而"内核到底是什么"，是一个仍在验证的开放问题。
4.3 我们还在寻找什么是真正的核心竞争力阅读 12 min▾
核心竞争力不是你宣称的优势，而是客户对比后"只有你能解决"的问题。

这一节我们不替公司下结论，而是列出正在被检验的候选答案——它们目前都还算不上被验证的护城河，只是量潮在与客户的对比中观察到的可能支点：

候选 A · 人才循环背靠高校，有充足的学生人才提供多元想法与足量支持——但高校合作很多公司也能做
候选 B · 科研数据工程经验已完成相关方向十余个完整项目，且每次项目都有完整记录与总结——但经验可以被对手积累
候选 C · 知识工程与标准化能力把经验沉淀为课程、工具和规则，而不是留在个人手里
候选 D · 产教融合闭环数据—人才—工具互相反哺，形成别人难以复制的系统

真正的判断标准只有一个：客户对比之后，发现只有你能解决的问题。你参与项目时观察到的"客户为什么选我们"，正是量潮检验核心竞争力的重要证据——欢迎你把观察带回来。

一句话记忆：核心竞争力 = 客户对比后只有你能解决的问题。目前是四个候选，等待真实业务来验证。
4.4 制度创新实验室：规则保护温情选修阅读 20 min▾
量潮把自己定位成"制度创新实验室"——规则，是它反复打磨的核心产品。

选修说明：这一节是创始人思考 / 组织实验，内容属于公司治理哲学，而不是"新人必须掌握的工作事实"。建议你先完成一些真实工作——在项目里经历过规则冲突、授权问题、责任边界之后，再回来读这节，理解会完全不同。

量潮不是一个标准的咨询公司，也不是单纯的培训机构，而是一个"实验室"：用科学方法不断试错迭代，去研发"制度"这个产品。它的三个层次：

定位制度创新实验室（手段）——规则的设计师、组织进化的工程师
使命做行业教科书（动作）——把混沌经验变成标准知识，把复杂管理变成可执行流程
愿景构建规则清晰、价值涌现的商业生态（结果）

两条底色：

  • 价值观"我即是标准" — 先把自己变成制度的"活标本"，验证这条路能走通，再把标准推演给行业
  • 方法论"自我淘汰" — 相信我会过时，所以迫不及待想证明自己错了，从而进化到下一阶段

在组织内部，这套理念落地为从"人治"走向"法治"：矩阵式组织架构、公司代表大会、透明化经营。制度的最终目的，是保护温情——让好的行为在规则里自然生长，而不是靠人情维系。

一句话记忆：实验室（身份）→ 写教科书（动作）→ 新生态（结果）；"我即是标准"，"规则保护温情"。
📌 本章小结 · 这些问题还没有答案

4.1 为什么尽可能公开？公开不是放弃护城河，是把信任成本砍掉——但永远清楚"哪些不能公开"。

4.2 为什么能做四件事？一个内核 × 四个方向——而"内核到底是什么"仍在验证。

4.3 什么是真正的核心竞争力？还在寻找：四个候选，等待真实业务来验证。

4.4 规则是为了什么？规则保护温情——这是创始人思考，建议完成真实工作后再读。

📝 五、微型创业：Sell Your Demo

发现机会，做出原型，说服总部下注。

前四章告诉你量潮从哪里来、在做什么、怎么做事，以及正在探索什么。现在轮到你给出自己的答案。

从真实用户和真实问题出发，发现一个值得量潮进一步验证的机会。你有两周时间，把判断变成一个可以被体验、测试或讨论的 Demo，然后向总部争取下一阶段资源。

这不是"交作业"——这是一次微型创业实验。你是项目 CEO，总部是你的内部投资人。总部不会给你出题，你自己发现机会、验证判断，并用 Demo 争取下一阶段资源。我们不要求你的判断一定正确，你需要证明的是：你能发现问题、形成假设、快速验证，并根据证据更新判断。

Sale 是什么？不是把 Demo"卖个好价钱"，而是说服总部相信这个机会值得继续投入资源。好的项目不一定是全新方向——也可能是已经做了但做得不好、有需求但没产品化、内部工具可变成外部产品、业务之间断点、或已有产品缺某类用户场景。

🎯 总部怎么评审？四个维度

机会价值 30% — 问题是否真实、值得解决

量潮匹配度 20% — 为什么是我们做，而不是别人

验证质量 30% — Demo 是否真正验证了关键假设

表达与复盘 20% — 是否说清楚学到了什么、下一步是什么

"是否成功"看的不是 Demo 漂不漂亮，而是：两周以后，我们是不是比两周以前更确定这件事该做还是不该做。

Demo 不等于完整产品。网页原型、数据集、自动化流程、AI Agent、课程原型、咨询方案、运营实验都可以。关键不是"做得大"，而是能验证一个重要假设。
